Zcash → NEAR Intents 1Click · wallet-side

A new refund address and recipient for every swap.

Every swap out of Zcash through 1Click names a refund address and a recipient in a public request. Lethe gives each swap a refund address used once and its own NEAR account, both from one seed, and tells you what still links them.

      What it forgets, and what it can't

      Every field of the three published requests, checked for what could link them.

        That first run cut the first row only. Since then a swap with no recipient goes to its own NEAR account, and a reused recipient is refused unless you accept the link. A shared 1Click token and your IP are still yours to manage.

        All three links, measured

        The refund address was the easy link. The recipient, the amount and the timing are the others. Both batches are scored from their real 1Click requests by the report the CLI and MCP print.

          Sweeping re-links. Moving several per-swap accounts into one account shows them all paying it, on chain. zswap sweep-plan flags that: leave each account alone, sweep each somewhere different, or swap each back into a shielded address at another time and amount. A token-only account needs NEAR for gas, and a top-up from your own account links it too.

          Found again, from the seed alone

          1Click has no testnet, so a demo provider wallet paid each one-time testnet address as a stand-in refund. A compact-block scan finds each payment with its own key only.

            Not yet

            • BLOCKEDA real swapA live quote creates a mainnet deposit address and needs mainnet ZEC and the maintainer's sign-off. So no real 1Click refund to a one-time address has been seen yet; the quotes above are dry.
            • Draft key derivationzakura-one-time-ivk 0.0.1-rc1 says it must not issue live addresses before review. Mainnet addresses appear here only in dry quotes.
            • Spending a refundThe one-time keys keep the account's spending authority, but this project does not spend a one-time note.
            • Delivery to a per-swap NEAR account1Click accepted each fresh implicit account in a dry quote; nothing was delivered, so no sweep has been run. Amount splitting and delays are planned by Lethe, not sent on a schedule by it.

            Run it

            Rust, a compact-block scanner, a CLI and an MCP server. The tests call the real 1Click API with dry quotes and scan Zcash testnet.

            pnpm install && pnpm test
pnpm --filter @zswap/cli zswap quote 0.1 nep141:wrap.near        # its own refund address and NEAR recipient
pnpm --filter @zswap/cli zswap plan 0.35 nep141:wrap.near --split --window 180
ZSWAP_BOOK=/nonexistent pnpm --filter @zswap/cli zswap recipients
ZSWAP_BOOK=/nonexistent pnpm --filter @zswap/cli zswap recover <from-height>
